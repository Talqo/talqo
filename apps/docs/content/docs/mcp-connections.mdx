---
title: Connect a tools server
description: Give an agent live data from your own systems.
---

A tools server lets an agent use live data such as stock levels, order status, or prices. It must support MCP, the protocol Talqo uses to discover and call its tools.

Each connection belongs to one agent. Credentials configured for one agent are not shared with another.

## Two kinds of connection

**Web address** runs the server somewhere you already host it and gives Talqo its address. Most servers work this way, and it is the easier option.

**Local program** runs the server as a child process on the machine running Talqo. Use it for servers you install yourself.

## Web address

Fill in the address the server publishes, usually ending in `/mcp`.

Use the authentication headers specified by the server, such as `Authorization: Bearer …` or `X-API-Key`.

## Local program

The command runs on your own server, as the same user Talqo itself runs as. Only point it at programs you trust.

Supply any credentials the program needs as environment variables. It does not inherit Talqo's secrets, such as the database password.

A Python-based server cannot run in the container as shipped, because it has no Python interpreter. Run those yourself over a web address instead.

## When something does not work

If a server is unreachable, its tools are unavailable for that message and the agent answers with what it has. Check Talqo's server log for the reason.

Failed connections remain saved. After fixing the server or connection settings, save the connection again to refresh its tool list.
